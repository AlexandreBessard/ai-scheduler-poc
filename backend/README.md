# Backend — AI Appointment Scheduler

Python backend powering the AI scheduling assistant. Customers describe what they need in natural language; a LangGraph agent orchestrates Claude to call the right tools and book the appointment.

---

## Stack

| Layer | Technology |
|---|---|
| API | FastAPI + Uvicorn |
| Agent orchestration | LangGraph (`StateGraph`) |
| LLM | Claude via `langchain-anthropic` |
| Natural language dates | `python-dateparser` |
| Config | `pydantic-settings` (reads `.env`) |

---

## Architecture

```
HTTP request (Angular client-app)
        │
        ▼
  FastAPI  (/chat)
        │
        ▼
  LangGraph graph  ◄──────────────────┐
        │                             │
        ▼                             │
   agent_node                         │
  (Claude + tools)                    │
        │                             │
        ├── tool_calls? ──► tools_node (ToolNode)
        │                        │
        │     ◄───────────────────┘
        │
        └── final answer ──► SSE stream ──► client-app


HTTP request (Angular admin-app)
        │
        ▼
  FastAPI  (/appointments)
        │
        ▼
  appointment_service  (no agent involved)
```

The agent follows a **ReAct loop**: Claude reasons about the user's request, decides which tool to call, receives the tool result, and continues until it can give a final answer. The loop is implemented as a LangGraph `StateGraph` compiled once at startup and shared across all requests.

The admin dashboard (`/appointments`) bypasses the agent entirely — it reads directly from the service layer.

### `app/main.py`
FastAPI application entry point. Registers the lifespan (compiles the LangGraph graph once at startup and stores it on `app.state`), mounts CORS middleware, and includes the two routers.

### `app/config.py`
Reads environment variables from `.env` using `pydantic-settings`. Exposes a `get_settings()` function cached with `@lru_cache`, injected wherever config is needed via FastAPI `Depends()`.

---

### `app/api/routes/`

| File | Endpoint | Consumer |
|---|---|---|
| `chat.py` | `POST /chat` | Angular **client-app** |
| `appointments.py` | `GET /appointments` | Angular **admin-app** |

**`chat.py`** — receives a `{ message, thread_id }` body, feeds it to the LangGraph graph, and streams the response back as Server-Sent Events (SSE). The `thread_id` (a UUID generated by the Angular client per session) is used as the LangGraph checkpoint key so conversation history is preserved across turns.

**`appointments.py`** — plain CRUD read endpoints. Calls `appointment_service` directly. No agent involved.

---

### `app/agent/`

The LangGraph ReAct agent.

**`state.py`** — defines `AgentState`, a `TypedDict` holding the conversation message list. Uses the `add_messages` reducer so new messages are appended rather than overwriting the state.

**`nodes.py`** — contains two functions:
- `agent_node` — calls Claude (bound with the four tools) and appends the response to state.
- `should_continue` — conditional edge: routes to `tools_node` if Claude made tool calls, or to `END` if it produced a final answer.

**`graph.py`** — assembles the `StateGraph`, wires the edges, attaches a checkpointer (`MemorySaver` for development, `AsyncPostgresSaver` for production), and exposes `build_graph()`. The compiled graph is created once in the FastAPI lifespan.

---

### `app/tools/`

Each file defines one `@tool`-decorated function. Claude reads the docstring and parameter descriptions to decide when and how to call each tool. Tools are thin — they validate input, parse dates, and delegate to `appointment_service`.

| Tool | What it does |
|---|---|
| `check_availability` | Returns available time slots for a given date and duration |
| `book_appointment` | Creates a new appointment and returns a confirmation |
| `list_appointments` | Returns appointments filtered by customer name or date |
| `cancel_appointment` | Marks an appointment as cancelled by ID |

`__init__.py` exports all four as a `tools` list, consumed by `agent/nodes.py` when binding tools to the model.

---

### `app/services/`

**`appointment_service.py`** — the single source of truth for appointment data. All tools and routes call this; nothing else touches storage directly. During the POC phase an in-memory dict is used. Swapping to a real database (e.g. SQLAlchemy + PostgreSQL) only requires changes here.

---

### `app/models/`

**`appointment.py`** — Pydantic v2 models shared across the whole application:
- `AppointmentStatus` — enum: `pending | confirmed | cancelled`
- `Appointment` — the core domain model
- `ChatRequest` — request body for `POST /chat`

---

### `app/utils/`

**`date_parser.py`** — wraps `python-dateparser` to convert natural language date/time expressions into timezone-aware `datetime` objects before they reach the service layer.

```
"tomorrow afternoon"   →  2026-05-26 14:00:00+00:00
"next Monday at 9am"   →  2026-06-01 09:00:00+00:00
"in two weeks"         →  2026-06-08 00:00:00+00:00
```

Configured with `PREFER_DATES_FROM: future` so relative expressions always resolve to the next upcoming occurrence, not a past one.

## Getting started

```bash
# 1. Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Configure environment
cp .env.example .env
# Edit .env and set ANTHROPIC_API_KEY

# 4. Run the development server
uvicorn app.main:app --reload --port 8000
```

API is available at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs`.

| Variable | Description | Default |
